# 0.3.3 held here until 2026-09-18, and for most of that time the MCP server did not work.
# It declares `mcp>=1.6.0` with no upper bound, and the SDK changed the wire wrapper inside
# that range: 0.3.3 feeds a bare JSONRPCMessage to a receive loop expecting SessionMessage,
# so the session is dropped at `initialize` with `'JSONRPCMessage' object has no attribute
# 'message'`. The application still imports and boots, which is why nothing caught it —
# ADR 0004's pin fixed the boot crash and left the runtime break in place. 0.4.0 requires
# mcp>=1.12.0, speaks the current wrapper, and adds the header allowlist app/main.py needs.
# See ADR 0033, and tests/unit/test_mcp_session.py, which now fails if this regresses.
