# Planning a project — the Natural Planning Model

runway stores a plan per project: `purpose`, `principles`, `vision`, `brainstorm`,
`organized`. These are the five steps of GTD's Natural Planning Model. Most projects need
no plan at all — a clear outcome and a next action are enough. Plan when a project is
stuck, vague, big, or keeps the user awake.

If the repository keeps project documents of its own and names them as the home of project
context, the plan lives there, not in runway. Use the runway plan for projects that have
no other home. One home per plan.

## The conversation

Ask, listen, write down the user's words. One step at a time, short.

1. **Purpose** — "Why are we doing this?" Keep asking why until the answer would let
   someone else make a decision for the project.
2. **Principles** — "What are the boundaries?" Budget, quality bar, who must be involved,
   what must not happen.
3. **Vision** — "What does wildly successful look like?" Present tense, concrete, as if it
   were already done. This is the definition of done.
4. **Brainstorm** — everything that comes to mind, unordered, unjudged. Quantity first.
   You may add ideas, marked as yours.
5. **Organize** — group and order: components, sequence, what is essential. Only now
   evaluate.

Save after each step (the plan accepts partial updates), so an interrupted session loses
nothing. Check the project name against the project list before writing — a plan for an
unknown name is created silently.

## It ends with a next action

A plan that does not produce a next action has not finished. From the organized list:

- create the first concrete `next` action,
- create the following steps as tasks in the project without a status tag, with `depends`
  only where the order is real,
- anything that needs someone else becomes a `waiting` item.

If the user cannot name a next action, the project is not clear yet — go back to vision,
or propose "decide whether to pursue this" as the honest next action.
