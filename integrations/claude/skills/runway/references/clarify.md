# Clarify — emptying the inbox

Clarifying is the user's thinking. You ask the questions, propose wording, and write the
result. Do not pre-sort the whole inbox and ask for a blanket approval: a user who only
nods has not decided anything, and the system stops reflecting their commitments.

Work strictly one item at a time, top to bottom. **Nothing goes back into the inbox.**

## The questions, in order

1. **What is it?** Read the item (and its note) aloud in one line.
2. **Is it actionable?**
   - **No** →
     - trash: complete or delete it (deleting needs a yes),
     - reference: it is not a task; file it wherever the user keeps reference material
       (in a repository with its own filing rules, follow those), then complete the item,
     - maybe later: tag `someday`, or turn it into a tickler with `wait`.
   - **Yes** → continue.
3. **What is the desired outcome? Does it take more than one step?**
   - More than one step → it is a project. Pick or create the project (check the name),
     and make *this* item the first concrete action. For big or fuzzy projects offer
     planning (`references/planning.md`), do not force it.
4. **What is the very next physical action?** Rewrite the description verb-first.
   - **Under two minutes** → the user does it now; then complete it. Only do it yourself
     if it is genuinely your action (e.g. looking something up in this repository).
   - **Someone else has to act** → `waiting`, annotation, `scheduled` for follow-up.
   - **Tied to a day or time** → it belongs in the calendar. Say so; add `due` only if the
     user wants the task as well.
   - **Otherwise** → `next` (if startable now), context, project.

## Pace

Keep each item to one short exchange. Offer a concrete proposal the user can accept with
"ja": *"‚Steuerberater' → ‚Steuerberater anrufen wegen Vorauszahlung', @phone, next?"* Accept shorthand answers. If the user is clearly tired after ten items,
stop at a clean point and say how many remain — a half-empty inbox is fine, a half-thought
item is not.

## Writing the result

One modify call per item: description, project, tags (status + context),
dates. If the server cannot remove tags, mention it once and carry on with what works.

End with a one-line tally: clarified, turned into projects, deferred, trashed.
